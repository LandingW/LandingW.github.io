# 文章工作流

## 1. 推荐：Markdown 原稿由自己掌握

在 `content/writing/` 新增英文小写短横线文件名，例如 `my-rendering-note.md`：

```markdown
---
title: "文章标题"
date: "2026-09-28"
description: "用一句话说明这篇文章。"
category: "渲染与光照"
draft: false
---

## 一个问题

这里写你准备公开的正文。
```

分类可选：`渲染与光照`、`引擎实践`、`学习笔记`、`随想`。
设置 `draft: true` 的文章不会出现在站点、RSS 或 sitemap。
日期必须为有效的 `YYYY-MM-DD`，文件名不要以保留前缀 `zhihu-` 开头。
文章将生成 `/writing/my-rendering-note/`，自动加入搜索与 `/feed.xml`。
首页置顶自动选取发布日期最新的一篇文章，使用完整发布时间排序，不再使用手动 `featured` 标记。新增文章后无需另行修改置顶配置。

不要在草稿中保存不能进入 GitHub 仓库的内容：draft 只控制页面展示，不是访问权限。

## 2. 迁移既有知乎全文，不改变站内链接

给自己的 Markdown 原稿添加：

```yaml
zhihu_id: "2027425907149652572"
source_url: "https://zhuanlan.zhihu.com/p/2027425907149652572"
```

上面只是已有文章 ID 的格式示例，请使用与原稿对应的真实 ID。
**长 ID 必须加引号**，避免 YAML / JavaScript 浮点精度损失。
如果缓存中存在该 ID，Markdown 正文会优先覆盖摘要，并沿用 `/writing/zhihu-对应ID/`。
来源链接被保留；有来源的转载页将 canonical 指向原始发布地址。
没有全文的缓存只显示摘要，并设置 noindex，避免制造重复的薄内容页面。

## 3. 知乎继续作为原始发布平台

直接运行 `python scripts/scrape_zhihu.py` 会尝试拉取全文，成功后存入 `content_html`。
该接口不是稳定的官方发布 API，可能受到 Cookie 过期、403、限流、返回结构变更影响。
本地验证中匿名访问接口返回 401 / 403；不能保证仅配置 Cookie 就一定恢复。
普通公开文章网页仍可能可读：本次已从正常可读的网页导入「我在腾讯做GI一年的经验 & 一个实习生对AI时代的思考」的正文作为站内全文示例，保留原文、图片外链与来源标记。其余 19 篇仍为摘要，全文覆盖率会在首页明确展示。这个一次性迁移不代表无人值守同步已经恢复。

如果拥有本人文章的合法 JSON 导出，可离线导入：

```sh
python scripts/scrape_zhihu.py --input path/to/my-export.json
```

支持单条文章对象、文章数组、`{"data": [...]}` 或 `{"articles": [...]}`。
每条需要 `id`、`title`、`created`、`updated`、`content`（HTML，或 `content_html`）。
时间戳以秒为单位；只有摘要的文件必须显式传 `--metadata-only`。
未知作者、无效分页和空全文不会伪装成成功。仅凭原网页的前 200 字无法还原正文。

## 4. RSS 与图片边界

- 本站 `/feed.xml` 是向外提供的 RSS，供阅读器订阅；不是偷偷调用第三方 RSSHub 抓取知乎。
- RSS 发布标题、摘要和本站文章地址。只有构建部署成功后线上内容才会更新。
- 知乎图片、公式图片仍可能依赖原站防盗链或登录策略。正文的图片会优先使用原图地址，设置 `no-referrer`，但不保证第三方资源永久可用。
- 更长久的方式是将自己拥有使用权的配图放进 `public/writing/`，Markdown 引用 `/writing/文件名.png`。不要直接搬运第三方图片或未公开项目材料。
- 代码围栏和表格可用。当前不执行 MDX/JS，也不加载 iframe；这是静态存档的安全边界。

## 5. 发布前的内容检查

先本地预览，再决定是否推送。工作介绍可以列举公开的技术栈与职责，但不加入内部项目缩写、算法、代码、未发布画面、平台指标和未经验证的性能收益。
同步缓存是自己的文章存档，不代表对平台或第三方内容有转载授权。
