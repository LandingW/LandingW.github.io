# 照片库与旅行编排

管理入口：<https://landingw.github.io/travel/manage/?view=library>

使用原来的管理密码。密码只留在当前页面内存，刷新后需要重新登录；无需提供 R2 密钥。

## 推荐流程

1. 在「照片库」新建文件夹，例如「2026 · 挪威」，选中该分类后批量上传照片。
2. 上传完成会启动现有 GitHub Actions 高清处理。页面可以关闭，稍后重新打开查看状态。中断的上传可在同一浏览器会话、同一文件夹重新选择原文件续传；已完成的文件不必重复上传。
3. 处理完成后勾选照片，选择旅行，再点「加入这次旅行」。一次最多操作 40 张，可以分批加入。
4. 在「旅行编排」调整照片顺序、选择最多四张封面、编辑地点和设备信息，保存后发布。没有旅行时先在这里创建一条。

原来的「直接上传到本次旅行」仍然可用，照片也会收入照片库。两种上传方式均不需要重新编译或部署网页。

## 整理与查找

- 文件夹是单层逻辑分类，可以创建、重命名，或将照片批量移动到另一分类。删除文件夹要求里面没有照片，包括回收站照片。
- 可按文件名或相机搜索，按已处理、待处理/失败、未加入旅行筛选。每批显示 40 张，按需继续加载。
- 点照片进入现有高清查看器，放大时按视野加载 Deep Zoom 切片，不一次下载整个原片。
- 「参数与 R2 文件」显示已有的摄影参数、真实存储路径和所属旅行。缺失的设备型号不会猜测填入。
- 同一张照片可加入多次旅行，每个旅行单独控制排序和发布；原片和切片只存一份。加入照片不会自动公开，需要再次发布旅行。照片顺序调整和移出操作会立即更新已发布旅行的清单。
- 当前整次旅行排序最多支持 100 张；照片库总量仍受原片 2 GB 配额约束。

## 三种删除的区别

| 操作                     | 影响                                             | 恢复与空间                       |
| ------------------------ | ------------------------------------------------ | -------------------------------- |
| 从旅行「移出旅行」       | 仅解除该旅行的关联，其他旅行不变                 | 可以从照片库重新加入，不释放空间 |
| 「删除这次旅行」         | 旅行进入回收站并从网站撤下                       | 可恢复为草稿，照片库不变         |
| 照片「移入回收站」       | 从所有公开旅行撤下，保留原关联为草稿             | 可恢复，不释放空间               |
| 回收站「永久删除此照片」 | 删除该照片原片、所有版本的缩略图/预览/切片和关联 | 不可恢复；清理完成后释放额度     |

恢复照片或旅行不会自动重新发布。正在上传、切片或读取 EXIF 的照片需要先取消上传或等待处理结束，才能移入回收站。

永久删除有独立确认框，按照片目录分批清理。如果网络中断，刷新状态后点击「继续永久删除」；已经开始清理的照片不能再恢复。

## R2 的存放方式与隐私边界

R2 不存在真正的目录；对象按稳定前缀存放：

```text
私有原片桶  originals/{photoId}/source
公开展示桶  photos/{photoId}/{revision}/
              thumbnail.jpg
              preview.jpg
              image.dzi
              image_files/...
```

管理页文件夹保存在 D1 数据库，不改变上述前缀。移动分类或改名不复制 30 MB 原片，也不重新生成切片，现有高清链接不会因此失效。旧照片已按原旅行自动归入分类，原来的照片编号、文件路径和发布状态保留。

请通过管理页删除照片，不要在 R2 控制台手工删除部分切片，否则数据库与照片库会失去一致性。

原片仍在私有桶。缩略图和切片继续使用已有公开展示桶，**未发布或移入回收站不等于这些展示文件变成私有**；知道直链的人仍可能访问。网站公开清单通常约 60 秒更新；永久删除后浏览器、CDN 或第三方缓存也可能暂存。需要严格保密的照片不要上传到这个公开影集方案。

页面顶部的 2 GB 是原片额度，不是整个 Cloudflare 账单上限。衍生文件另计，回收站保留的文件也占空间；复用照片、移动分类不重复计费存储。
