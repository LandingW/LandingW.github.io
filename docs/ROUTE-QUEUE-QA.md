# 多地点行程与自动处理验收

日期：2026-10-13。

## 使用方法

在「旅行编排 → 旅行信息」中搜索具体酒店、景点或地名，点选结果加入下一站。也可选择「在地图上添加一站」，再拖动编号图钉微调。左侧站点列表可以拖动排序，手机和键盘可用前移/后移按钮。每一站可设置名称、类型、小记或精确经纬度，最后点击底部「保存修改」。最多 40 个站点。

已发布旅行保存后更新公开行程，R2 清单缓存约 60 秒。未发布旅行仍为草稿。删除一个站点只修改当前旅行草稿，不删除照片。原来的旅行总览图钉移至可选折叠区，不自动覆盖；未设总览点时以第一站、照片 GPS 依次回退。

公开页用编号列表、站点详情和大地图呈现路线。弧线仅表示手动编排顺序，不是道路导航，也不从照片时间推断实际走过的轨迹。相机、镜头、EXIF 和高清切片仍保留原有逻辑。

## 设计与服务选择

- 参考 [Polarsteps Travel Planner](https://www.polarsteps.com/travel-planner) 的有序停留点与地图联动信息结构；延续本站纸色、墨色、朱红、小编号和留白，不引入另一套 UI 风格。
- 使用 Leaflet / OpenStreetMap。后台点击搜索时才调用 [Photon](https://github.com/komoot/photon) 的[公开 API](https://github.com/komoot/photon/blob/master/docs/api-v1.md)，不逐字自动补全、不批量搜索、不自动反查照片 GPS、不请求设备定位权限。
- 公共 Photon 适合合理小流量，不保证地点覆盖率或可用性。最多返回六项，服务端 1.2 秒限速、七天缓存；失败可改用图钉或坐标。`PHOTON_API_URL=disabled` 可关闭检索，或配置兼容服务。无需 Google key 或计费配置。
- 手机地图默认锁定，避免劫持页面滚动；点击「操作地图」再拖动。分形由两块全高大图改为五块较小图案，单块 `max(220px, 32lvh)`，保留 2s 生长 / 1s 保持 / 2s 消退与滚动偏移。动画尊重 reduced-motion。

## 自动处理修复

旧浏览器逻辑在整批上传完后才请求 Actions。中途失败、关闭页面，或请求未送达，会留下 queued 原片。用户确认手点「处理待办」即可启动，现有处理凭据和切片器无需更换。

现在每张原片完成上传后由 Worker 安排处理；90 秒原子调度锁合并并发请求，有有效处理租约时不重复触发，五分钟 cron 补查遗漏或过期租约。空队列不启动 Actions。重试失败照片也会自动安排。前端在新后台启用后不再额外发出整批处理请求，保留手动按钮和旧后台兼容路径。

照片库显示 queued、processing 计数和最后调度状态；授权或上游错误转为安全提示，不输出密钥。自动处理只生成预览/切片，不自动发布照片、不触发 Pages 构建。需要等原片上传完成再关闭页面，未完成的上传仍需重新选择相同文件续传。
